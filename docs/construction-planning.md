# 施工計画の定義

`construction-planning@1.0.0` は、建物・塔・橋などの構造物を、設計の情報と敷地の条件から、どう分けて、どの順に、どの機械と経路で建てるかを計画し、その計画を日付ごとの模型で動かして確かめ、承認を経て関係者に説明できる形にする汎用定義です。題材・工法・道具・出力形式は固定しません。既存の format 1 の schema を使います。

**11工程・11成果物・13項目・27引用／網羅規則・32達成条件**。各工程に人が確かめる達成条件があります。AI の達成条件は、見出しと項目の抜け、出典と確からしさの記入、引用と網羅に限ります。工法の良し悪し、施工中の安全、構造の安全を AI の合格だけで決めません。

## セクションと工程

| セクション | 工程 | 主な成果物 |
|---|---|---|
| 企画 | 進め方 → 与条件の整理 | 進め方、与条件 |
| 計画 | 施工用のモデル → 施工方法の選定 → 工程計画 → 揚重・搬入・仮設の計画 | 施工用のモデル、施工方法、工程表、揚重・搬入・仮設の計画 |
| 検証 | 施工の模擬・安全の確認・施工中の構造の確認（並行） | 施工の模擬の記録、安全の確認、施工中の構造の確認 |
| 判断と伝達 | 計画の承認 → 説明と記録 | 計画の承認、説明と記録 |

`after` は工程の**受け入れ順**です。模擬で見つかった事項を直すと、工程表や揚重の計画の新しい版ができます。そのときは影響する模擬・安全・構造の確認をやり直し、承認は最後の版に対して行います。循環する工程は定義しません。

## 使い方と省略

対象と出口を「進め方」に書きます。小さな建物で揚重機を使わない、仮設の支えが無い、施工中の構造が完成時より明らかに楽、などの場合は、工程を省く理由と代わりの確認を書きます。

題材が実在の構造物のときは、公開された情報から作った近似であること、その構造物の持ち主・設計者・施工者とは関係が無いことを「進め方」と「説明と記録」に書きます。持ち主や施工者の名前・標章を、関係があるように見える形で使いません。公開されていない寸法や工程は「与条件」で仮定として書き、確かな情報と分けます。

人と AI が一緒に計画するときは、AI に任せる作業（モデルの分割、工程の並べ替え、模擬の実行、事項の一覧化など）と、人が決めること（工法、工期、危険の受け入れ、承認）を「進め方」に書きます。

## 項目と引用

| 項目 | ID | 置く成果物 |
|---|---|---|
| 条件 | CO-{nn} | 与条件 |
| 施工単位 | WU-{nnn} | 施工用のモデル |
| 工法 | MT-{nn} | 施工方法 |
| 作業 | TK-{nnn} | 工程表 |
| 節目 | MS-{nn} | 工程表 |
| 揚重機 | EQ-{nn} | 揚重・搬入・仮設の計画 |
| 経路 | RT-{nn} | 揚重・搬入・仮設の計画 |
| 仮設物 | TW-{nn} | 揚重・搬入・仮設の計画 |
| 模擬の事項 | SI-{nnn} | 施工の模擬の記録 |
| 危険 | HZ-{nn} | 安全の確認 |
| 解析の場合 | AC-{nn} | 施工中の構造の確認 |
| 判断 | DC-{nn} | 計画の承認 |
| 説明の場面 | PS-{nn} | 説明と記録 |

主な引用は、**工法 → 施工単位、作業 → 工法（と施工単位・先行の作業）、節目 → 条件・作業、揚重機 → 工法・作業、経路と仮設物 → 作業、模擬の事項と危険 → 計画の対象、解析の場合 → 作業、判断 → 事項・危険・解析の場合、説明の場面 → 節目か作業**です。

網羅では、すべての施工単位に工法と作業があること、すべての工法が作業に使われていること、すべての模擬の事項と危険に判断があることを確かめます。条件・節目・解析の場合は、理由を書けば `exempt` で除けます（たとえば、工法や節目に結びつかない近隣の約束は、安全の確認で扱うと書く）。

## 模擬で確かめること

施工の模擬は、工程表と揚重・搬入の計画を、日付ごとの模型で動かして確かめる工程です。利用側の道具に応じて、たとえば次を検査します。

- 揚重機が吊る所と据える所に届くか、その半径で定格荷重に収まるか。
- 吊る経路と旋回の範囲が、その日に立っている部材・仮設物・地面とぶつからないか。揚重機が昇ったあとも同じか。
- 部材を据える日に、それを支える部材が立っているか。引き上げる部材は、引き上げる前の低い所で据えているか。
- 搬入の車が、吊りの時刻より前に、作業の時間の中で着くか。ゲートと経路が重ならないか。

検査で出た事項は一件ずつ「模擬の事項」にし、直したか、受け入れたか、持ち越したかを書きます。直して消えた事項も、直した版を書いて残せます。模擬の映像は人が見て、検査で拾えない不自然さ（吊り荷の向き、車の動き、順序の違和感）を確かめます。

## 評価と承認の境界

- AI は見出しと項目の抜け、出典の無い条件、引用と網羅の切れ、処置の無い事項を指摘します。模擬の検査の結果は、検査が扱った範囲の結果として扱います。
- 人は工法・工期・揚重機の選定・危険の受け入れ・施工中の構造の結果を決めます。安全と構造は、それぞれの責任者が確かめます。
- 定義の検査が通っても、実際の施工の安全や法令への適合を保証しません。

## 利用側が受け持つこと

- **モデルと実体**：設計のモデルを施工単位に分け、重さと材料を持たせる道具。施工単位と項目の対応。
- **日付ごとの模型と検査**：工程の日付から、その日に立つ部材・揚重機の高さ・車の位置を出し、届く・重さ・ぶつかり・支え・時間を検査する道具と、その速さ。
- **映像**：日付を追う映像の書き出しと、場面ごとの版の記録。
- **構造の解析**：段階ごとの解析の道具と、その仮定の確からしさ。

## 検証

`npm run check` が正式な必須検査です（schema の生成物の整合、定義の検査、契約試験）。定義の検査は計画の安全や完成を保証しません。
