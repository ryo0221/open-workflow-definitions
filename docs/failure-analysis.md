# 故障の原因解析と対策

[定義](../definitions/failure-analysis.json) は、起きた・起こり得る故障を、要因分析（特性要因図）・FMEA・FTA の三つの分析で調べ、対策と確認まで進めるための進め方です。製品・工程・サービスのどれにも使えます。

三つの分析の項目は**別の意味と ID のまま**持ち、明示した引用でつなぎます。原因の候補・故障原因・基本事象を同じものとして扱わず、文章の中の言及や名前の一致から引用を作りません。この進め方は、認証や承認された安全評価の代わりではありません。

横断の設計判断：[tokiwa-ecosystem 0001](https://github.com/ryo0221/tokiwa-ecosystem/blob/main/docs/decisions/0001-analysis-element-references.md)。

## 工程と成果物

| 工程 | 成果物 | 主な判断 |
| --- | --- | --- |
| 対象と問題 | 問題の定義 | 対象の機能、起きた事象、確かめた事実と仮定、範囲の外 |
| 要因分析 | 要因分析（特性要因図） | 原因の候補、分類、根拠、状態（仮説・確認済み・除外） |
| FMEA | FMEA | 故障モード・影響・故障原因、評価の表と点、優先度の決め方 |
| FTA | 故障の木 | 頂上事象の定義、ゲート、基本事象、確率とその仮定 |
| 対策と確認 | 対策と確認 | 故障原因ごとの対策、担当と期限、効果の確認 |
| まとめと受け入れ | 解析の報告 | つながり、残るリスクと制限、続けるか閉じるか |

工程は **問題と原因 → 故障の解析 → 対策と受け入れ** の3つのまとまりにしています。各工程に、人が成果物を確かめて承認する達成条件があります。

## 項目・引用・網羅

| IDの形 | 項目 | 内容 |
| --- | --- | --- |
| `FN-{nn}` | 機能 | 対象が果たすべき機能と使われる条件 |
| `PB-{nn}` | 問題 | 起きた・起こり得る事象、条件、影響 |
| `CC-{nn}` | 原因の候補 | 特性要因図の候補。分類・根拠・状態 |
| `FM-{nn}` | 故障モード | 機能の故障のしかた、影響、深刻さ |
| `FC-{nn}` | 故障原因 | 故障モードを起こす原因、起きやすさ、管理、見つけやすさ |
| `TE-{nn}` | 頂上事象 | 故障の木の頂上の事象と、その定義 |
| `BE-{nn}` | 基本事象 | 故障の木の基本事象。確率を使うなら値と仮定 |
| `AC-{nn}` | 対策 | 故障原因への対策、担当、期限、状態 |
| `VR-{nn}` | 確認 | 対策の効果を確かめた結果 |

引用は下流が上流を引きます。三つの分析をつなぐ引用は次の二つで、どちらも任意（`min: 0`）です。

| 規則 | 引用 | 意味 |
| --- | --- | --- |
| `failure-cause-cites-cause-candidate` | `FC → CC` | 根拠：要因分析の候補を、故障原因として取り上げた |
| `basic-event-cites-failure-cause` | `BE → FC` | 対応：故障の論理の中で、その故障原因を事象として表した |

ほかに `PB → FN`、`CC → PB`、`FM → FN`、`FC → FM`、`TE → PB`、`AC → FC`、`VR → AC` を定義しています。原因の候補から基本事象へ直接は引きません。
1.1.0 から `strictCites: true` を宣言しています。引用は、この表の組だけです。規則に無い組（`FC → BE` のような逆向き、`BE → CC` のような飛び越し）を、利用側は違反として出し、その引用を持つ工程の受け入れを止めます。Editor の「候補から選ぶ」でも選ばせません。
上流の項目が変わったら、引用を逆にたどって見直しの要る下流が出ます（例：`CC` が変わると、それを引く `FC`、さらにその `FC` を引く `BE` と `AC`）。

網羅は、問題ごとの原因の候補、故障モードごとの故障原因、故障原因ごとの対策、対策ごとの確認です。どれも理由を書けば除けます。

## 利用側が受け持つこと

- 原因の候補の状態（仮説・確認済み・除外）は項目の欄です。除外した候補を引く故障原因を止めるか知らせるかは、利用側の道具が決めます。
- AI や道具が出した引用の提案は、人が採るまで引用として数えません。
- 引用は、成果物の外の引用の表か、引用する側の項目の構造化された参照の欄に持ちます（[README](../README.md) の「項目と引用」）。
- 評価の点の付け方、RPN や優先度の決め方、確率の出どころは成果物に書きます。この定義は FTA の確率から FMEA の起きやすさを、RPN から優先度を自動で決めません。確率の独立や共通の原因も保証しません。
