# 物語の時間・提示・世界線（fiction-novel 1.1.0）

`fiction-novel@1.1.0` で、出来事・シーン・提示位置と、時間・世界線をどこに書くかを決めました。ここは用語と記述の規約です。人物が何を知っているか、矛盾しているかを判定する仕組みは定義に置かず、利用側が受け持ちます。

## 用語

| 用語 | 意味 | 置く場所（成果物 / 見出し） |
|---|---|---|
| 出来事（EV） | 世界で起きたこと。シーンが一つも無くてよい（裏の出来事） | 筋の台帳 / 出来事 |
| シーン（SC） | 一つ以上の出来事や筋を描く場面カード。視点が違えば別のシーンにして同じ出来事を引用する | シーンカード / シーン |
| 提示位置（OC） | 作品の中でシーンを読者に示す一回。同じシーンの再提示は別の提示位置 | 構成図 / 提示位置 |
| 原稿の箇所 | 章原稿の中の段落などの範囲。提示位置との対応は利用側の対応表が持ち、定義の項目にしない | 章原稿（本文）と利用側の対応表 |
| 世界線 | 作品の中の一つの世界。親は一つまで | 世界の覚え書き / 世界線と時計 |
| 個体 | 人物（CH）が、ある世界に属する一人として現れたもの。同じ人物でも世界が違えば別の個体 | 出来事・経験の順・移送の中で、人物とその世界を組で書く |

世界線は、制作上の案（A案・B案）、成果物の版、正史として採るかどうかとは別のものです。

## 一つのことは一か所に書く

| 情報 | 唯一の置き場所 | 他の場所での扱い |
|---|---|---|
| 作中の時刻・精度・ほかの出来事からの日数 | 筋の台帳の出来事 | シーンは出来事を引用するだけで、時刻を書き写さない |
| 読者への提示順と話・章 | 構成図の提示位置 | 出来事の提示箇所は、描くシーンの提示位置からたどる。シーンカードに並びを書かない |
| シーンの関わる世界 | 書かない | 引用する出来事の世界と、受け継ぎの集合から導く |
| 人物の経験の順 | 構成図の人物の経験の順（作品ごと） | 人物表は変えない。ほかの作品の経験の順とつなげない |
| 受け継ぐ共通の過去 | 世界の覚え書きの世界線と時計 | 集合と固定した版で書く。分岐の時点から集め直さない |
| 世界間の移送 | 世界の覚え書きの世界間の移送 | 時刻の計算（出来事の「ほかの出来事からの日数」）とは別に書く |
| 診断の例外 | 単体の出来事の例外はその出来事、読者への開示の例外は構成図、在場・複数の出来事・移送・作品の外の出来事への例外は世界の覚え書き | 一つの診断に一件。対象が複数でも各出来事に写さない |

編集の記録の「残した例外」は、通読したときの作者の判断の記録です。上の診断の例外を引用して理由を書けます。

## 引用の書き方

- **同じ成果物の中**は ID だけで引用する（例: 台帳の中で EV-102 が EV-101 から日数を数える）。その成果物の、いま見ている版の中で読む。
- **別の成果物**は、固定した版をつけて引用する（例: シーンが出来事を、世界Bの台帳が世界Aの出来事を引用する）。相手の新しい版ができても、引用し直すまで古い版を読む。
- 診断で「この引用を新しい案へ向けたら」と試すのは利用側の仮の入力で、成果物の引用を書き換えない。
- 引用には、どの範囲に頼っているか（全体・時刻・中身・ある情報など）を添えてよい。範囲の種類と、添えないときの扱いは利用側の契約（EP の `tl-deps/1`）が決め、この定義では決めない。

## 時刻の書き方

- 時刻は時計ごとの相対の日で書く。負の日（原点より前）を使ってよい。実在の暦の日付に置き換えない。
- 「時刻未定」「日3のどこか」「日3になった瞬間」「日2から日4まで」「早くて日3、遅くて日5」を区別して書く。分からない値を 0 や今日にしない。
- 同じ日の二つの出来事の前後は、前後の関係として書く。同じ日だというだけで前後を決めない。
- 「EV-101 の 1 日後」は日数の関係、「最低 2 日かかる移動」は作者が決めた所要日数として書く。地名や距離から日数を決めない。
- 別の時計との比較は、整数日の差を書いた場合だけできる。

## 利用側との対応

定義の検査（`node scripts/check.mjs`）は、項目・引用・網羅の形を確かめます。作品のデータの形、時刻の計算、知識・開示・在場の判定、版の固定と保存は検査しません。

| 利用側 | 受け持つこと | 契約 |
|---|---|---|
| Editor Platform | 物語タイムラインの表示・操作、各成果物の native 編集と原稿の往復 | [T0契約](https://github.com/ryo0221/editor-platform/blob/main/docs/story-timeline/t0-contract.md)（`story-timeline-t0/1`、表の列 `tl1`、依存の規則 `tl-deps/1`）と同じ場所の fixture |
| PaoBub | 作品の成果物から索引を作り、時点・世界・認識・開示・権限を解決し、変更の影響と再確認の候補を出す。採用・承認は既存の判断の経路 | PaoBub の T0 契約（`docs/design/tl0-test-contract.md`） |

利用側は、上の契約の fixture（一作品・二世界・三人・九つの出来事）を共通に使い、利用側ごとに別の既定を作りません。表の列（`tl1`）、引用の範囲（facet）、依存の規則（`tl-deps/1`）は EP の T0 契約（editor-platform #642）が正本で、この定義はそれらの既定を持ちません。下の対応表は、定義の見出しが利用側のどの行にあたるかを示すだけです。

### 受入の確かめ方（定義の検査と、作品のデータでの受入）

| 確かめ | 何を見るか | どこで |
|---|---|---|
| 定義の検査 | 規則 `occurrence-cites-scene` と受入条件 `scene.occurrences-traced` が定義の中でつながっていること（規則・項目・対象の成果物があり、シーン設計の成果物を対象にしていること） | `node scripts/check.mjs`。作品のデータは読まない |
| 作品のデータでの受入 | 構成図にある**すべての**提示位置（OC）が、シーン（SC）を 1 件以上引用していること | 利用側の規則の評価。PaoBub の `evaluateRule` は、成果物（受入条件の対象）によらず、索引の中の `occurrence` の項目を全部数える。受入のゲート（`ruleGate`）は、どの工程の受入でも定義の規則を全部評価する |

受入条件の対象を `scene-cards` にしたのは、同じ工程の `scene.approved` と同じく「シーン設計で受け入れる」ことを示すためで、確かめる範囲を狭めるためではありません。

PaoBub の `evaluateRule` に、この定義の規則と小さな索引を渡して確かめた結果（手元で実行。作品のファイルからの索引づくりは利用側の T2 で足すため、まだ流していない）：

| 例 | 結果 |
|---|---|
| 正例：OC-001→SC-001、OC-002→SC-002。SC-003 には提示位置がまだ無く、原稿も無い | 違反なし（シーンに提示位置が無いことは、この規則の違反ではない。定義に「シーンを提示位置が引用する」網羅の規則は無い） |
| 負例：OC-003 がどのシーンも引用していない | OC-003 が違反（scene の引用が 0 件） |
| 負例：OC-004 が出来事（EV）だけを引用している | OC-004 が違反（シーン以外の引用は数えない） |

### 1.0.0 からの移行

1.0.0 の出来事・シーンカードに書いた提示順と章の割り当ては、**自動では移しません**。作者が構成図の提示位置へ移します。正本が二つにならないよう、移すときは次を確かめます。

- [ ] 提示する一回ごとに、構成図の「提示位置」に OC を一つ作り、示すシーンを引用した（同じシーンを二度示すなら OC を二つ）。
- [ ] 提示の並びと話・章は OC にだけ書いた。
- [ ] 出来事の説明から、提示順・提示する章の記述を消した。
- [ ] シーンカードから、並び（番号・前後）と章の割り当ての記述を消した。
- [ ] 消す前の記述と、新しい OC の並びが一致することを作者が確かめた（`scene.approved`）。
- [ ] 1.0.0 の版（固定した版・受け入れ済みの版）は書き換えていない。移行は新しい版として行う。

移行の途中で、出来事・シーンカードに並びが残ったまま OC もある状態は「正本が二つ」です。利用側はこの状態で、出来事・シーンカードの並びを提示順として読みません。

### 項目と利用側の列の対応（`tl1`）

| 定義の項目・見出し | 利用側の行の種類 |
|---|---|
| 出来事 | `event` と、出来事が持つ `derive-time` `after` `travel-min` `cause` `participant` `knows` `info-use` `claim` `fact` `presence` `exception` `exception-basis` |
| シーン | `scene` と `cite` |
| 提示位置 | `occurrence` |
| 人物の経験の順 | `experience` |
| 世界線と時計 | `clock` `worldline` `clock-offset` `inherits` |

## この版で変えないこと

- 定義の形（format 1）と、他の定義。
- シーンの ID が章によらないこと、引用の規則（シーン→出来事・筋・人物・場所、章→シーン）。
- 1.0.0 の成果物を読む利用側の扱い。提示順の移し方は上の「1.0.0 からの移行」のとおりで、自動では移しません。
