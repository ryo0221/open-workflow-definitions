# 小説の制作の定義

`fiction-novel@1.2.0` は、小説を企画から出版準備まで進めるための汎用定義です。作品の題材、長さ、出口、使う道具やファイルの場所はプロジェクト側で決めます。schema は既存の format 1 のままです。

12工程・21成果物・39達成条件です。どの工程にも作者が確かめる条件があります。AI が確かめる条件は、項目どうしの引用・網羅・抜けと、決めた表記の照合に限ります。作品の良し悪しを AI の条件で合格にはしません。

## 工程のセクション

| セクション | 工程 |
|---|---|
| 企画 | 進め方、企画 |
| 物語設計 | 人物、世界と舞台、筋と構成、シーン設計 |
| 執筆 | 執筆、推敲 |
| 仕上げと公開 | 校正、通読、出版準備、学び |

人物と世界と舞台は、企画の後に並行して進められます。定義の sections は既定のまとまりで、全工程を直列にするゲートではありません。after は受け入れの順です。前の工程を受け入れる前に、作者が先の章を試し書きしてかまいません。ただし試し書きを、その工程の受け入れや前提を満たしたことには数えません。

## 地図と絵を使う作品

本文だけの小説は、これまでの工程と成果物だけで仕上がります。地図や絵を使う作品では、次の成果物も作ります。使わないものは、進め方の「省く工程」に省くと書いて空にします。

| 工程 | 成果物 | 中身 |
|---|---|---|
| 企画 | 画作りガイド | 画作りの決まり（AR）・**レイヤーの決まり（LY）**・採用見本（SM） |
| 人物 | 人物の設定画 | 人物ごとの正面・側面・表情・衣装と、使ったレイヤー |
| 世界と舞台 | 地図、舞台の設定画 | 場所（LO）の位置・向き・縮尺と道、場所ごとの見え方と使ったレイヤー |
| シーン設計 | ストーリーボード | シーンごとの要の場面の絵、人物の配置とカメラ、使ったレイヤー |

画作りガイドとレイヤーの決まりは、漫画の定義 [`fiction-manga`](fiction-manga.md) と同じ項目（`art-rule`・`layer`・`sample`）と書き方です。レイヤーごとに、名前・重ね順・描く中身・使う段階・分けたまま残すか・人と AI のどちらが描いてよいかを書きます。決まりに要るレイヤーがそろっているかは AI が、絵の出来と人物・場所の同一性は作者が確かめます。

文体（文体ガイド）と画風（画作りガイド）、世界の事実（世界の覚え書き・地図）は別の成果物です。場所の項目（LO）は世界の覚え書きに置いたままで、地図と設定画はそれを指します。

## 項目と引用

| 項目 | ID | 置く成果物 |
|---|---|---|
| テーマ | TH-{nn} | 企画書 |
| 文体の決まり | SR-{nn} | 文体ガイド |
| 画作りの決まり | AR-{nn} | 画作りガイド |
| レイヤー | LY-{nn} | 画作りガイド |
| 採用見本 | SM-{nn} | 画作りガイド |
| 人物 | CH-{nn} | 人物表 |
| 場所 | LO-{nn} | 世界の覚え書き |
| 用語 | TE-{nn} | 固有名詞と表記の辞書 |
| 筋 | PT-{nn} | 筋の台帳 |
| 出来事 | EV-{nnn} | 筋の台帳 |
| 伏線 | FS-{nn} | 筋の台帳 |
| シーン | SC-{nnn} | シーンカード |
| 提示位置 | OC-{nnn} | 構成図 |
| 章 | CP-{nn} | 章原稿 |
| 指摘 | RV-{nnn} | 推敲の記録 |
| 学び | LE-{nn} | 学びの記録 |

シーンは章を親にしません。シーンを別の章へ移しても ID は変わらず、引用もそのまま残ります。章の並び順は利用側が持ちます。

読者への提示順は、構成図の提示位置だけに書きます。出来事にもシーンカードにも提示順の欄はありません（出来事の提示箇所は、その出来事を描くシーンの提示位置からたどります）。時間・提示・世界線の書き方は[物語の時間・提示・世界線](fiction-novel-timeline.md)にまとめました。

人物や筋を変えたときの影響は、引用をさかのぼって出します。引用のない本文に影響がないとは言えません。本文から読み取った矛盾の疑い（誰がいつ何を知っていたか、同じ時刻に二か所にいないかなど）は、引用の規則では確かめられません。利用側が候補として示し、作者が判断します。信頼できない語り手、時系列の仕掛け、意図したミスリードは、編集の記録に理由つきの例外として残します。covered の規則で扱わない筋と伏線は、理由を書いて除けます。

## 利用側が受け持つこと

次のことは定義に書かず、利用側が受け持ちます。

- **章ごとの反復。** 執筆・推敲などを章ごとに進めるときの単位、単位ごとの状態、引用先の版が変わったときの再確認。`outline.repeat` は見出しの繰り返しであり、工程の反復には使いません。
- **AI に頼む範囲。** 進め方で決めた範囲（読むだけ・作者の文への提案・下書きなど）を、章ごとの設定と権限として守ること。AI の役割の種類は定義に入れません。
- **提案の採否と来歴。** AI の提案は、作者が採るまで原稿に入れません。採否と作者の手直しを記録し、出版準備の「AI の関わり」に使えるようにします。
- **版。** 受け入れた成果物の固定した版と、出力のもとにした版の記録。

## 漫画の定義との関係

漫画の制作の定義 [`fiction-manga`](fiction-manga.md) とは、企画・人物・筋と構成・通読・出版準備・学びの工程と、人物・場所・出来事・筋・伏線・シーンの項目の名前をそろえます。小説を漫画にするときは、漫画の脚本の工程から、小説のシーンの固定した版を引用します。二つの定義を一つにまとめるかは、両方を使ってから決めます。

検査: `node scripts/check.mjs`。これは定義の形と参照の検査です。作品が完成したことは検査しません。
