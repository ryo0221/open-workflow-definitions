# 新規事業の企画の定義

`new-business-planning@1.0.0` は、会社の新規事業を、要る仕事の洗い出しから、機会の探索・仮説・市場と顧客・事業モデル・実行の計画・収支・リスク・投資の判断を経て、事業計画書と説明の資料にまとめ、経営の判断を受けるまでの汎用定義です。題材・手法・道具・出力形式は固定しません。

**13工程・13成果物・25項目・34引用／網羅規則・44達成条件**。各工程に人が確かめる達成条件があります。AI の達成条件は、見出しと項目の抜け、数字の種類と出典の記入、再計算の一致、資料と計画書・収支の数字の一致、スライドの読みやすさ、引用と網羅に限ります。事業の良し悪し、数字の確からしさ、投資と経営の判断を AI の合格だけで決めません。

## セクションと工程

| セクション | 工程 | 主な成果物 |
|---|---|---|
| 探索 | 進め方 → 機会の探索 → 事業の仮説 | 進め方（要る仕事のマインドマップ）、機会の探索（探索の枝のマインドマップと機会）、事業の仮説 |
| 確かめと設計 | 市場と顧客 → 事業モデル → 実行の計画 → 収支計画 → リスクと対策 → 投資の判断 | 市場と顧客、事業モデル、実行の計画、収支計画、リスクと対策、投資の判断 |
| まとめと説明 | 事業計画書 → 説明の資料 → 経営の判断 | 事業計画書、説明の資料、経営の判断 |
| 学び | 学び | 学び |

`after` は工程の**受け入れ順**です。前提を変えて収支が新しい版になったら、その版を引くリスク・投資の判断・計画書・説明の資料を確かめ直し、経営の判断は最後の版に対して受けます。

ゲートにあたる承認は 3 つです。

1. **事業の仮説**（`hypothesis.gate`）：事業の企画を受け持つ責任者が、仮説を確かめる価値があるかを決める。
2. **投資の判断**（`investment.committee`）：投資を審査する人たちが、進め方で決めた組織と人数のとおりに承認する。財務と法務・リスクの両方、などを進め方に書く。
3. **経営の判断**（`decision.approved`）：経営として判断する人が、判断と条件を承認する。

## 工程を決める工程

進め方では、この企画で要る仕事・成果物・判断・条件を、項目「要る仕事」（ND）としてマインドマップに広げてから、使う工程と省く工程を決めます。企画・財務・法務など、それぞれの役割が枝を足し（欄 `by`）、どの枝がどの工程・成果物・達成条件になったかの対応を「工程と成果物」に書きます。この定義そのものを、そうやって作ったときの対応を残すためです。

工程の定義を途中で変えるときは、差分を確かめてから新版として承認します（`process.approved`）。

要る仕事と探索の枝は、欄 `parent` に親の枝の ID を持ち、マインドマップ（`as: "mindmap"`）で見せます。事業モデルは関係者を点・流れを線・領域を枠にした図、実行の計画は拠点と経路の図と節目のタイムラインで見せます。

主な引用は、**機会 → 探索の枝、仮説 → 機会、顧客の話 → 仮説、流れ → 関係者、拠点 → 関係者、経路 → 拠点、シナリオ → 前提、計算結果 → シナリオか前提、リスク → 前提・計画・関係者・計算結果、段階の投資 → 計算結果か節目、撤退の基準 → 指標・前提・リスク、主張 → もとの項目、スライドと想定問答 → 主張、判断 → 資料・主張・撤退の基準**です。これで、説明の資料の数字から、主張・計算結果・前提・出典までたどれます。

網羅では、どの仮説も顧客の話か市場の数字で確かめられていること、すべてのシナリオに計算結果があること、すべての撤退の基準が計画書か判断で扱われていることを確かめます。探索の枝・機会・前提・リスク・計算結果・主張は、理由を書けば `exempt` で除けます（捨てた機会、本文だけで扱うリスクなど）。

## 数字の種類

市場の数字と前提は、欄 `kind` で種類を分け、種類ごとに持つものを決めます。

| 種類 | 持つもの |
|---|---|
| 実績 | 出典、対象の地域、対象の年、単位 |
| 予測 | 出典、予測の条件やシナリオ |
| 仮定 | 仮定であること、理由、想定する幅 |
| 計算 | 使った数字と、計算モデルの版 |
| 条件（前提だけ） | 割引率・税・期間など、会社や計画で決める値と、その理由 |

収支計画では、計算の条件（期間・年次か月次か・基準の通貨・割引率・税・丸め・計算モデルの版）を書きます。複数の通貨を使うときは、基準の通貨を一つ決め、換算率を前提として持ちます。計算結果は、書いた前提と計算モデルの版から再計算でき、値が一致することを AI が確かめます（`business-case.recomputable`）。

## 見せる範囲

提携先など社外の人と一緒に作る成果物があるときは、見せる成果物と見せない成果物、範囲を分ける単位、受け渡す版を進め方に書きます。範囲をどう分けるか（別のリポジトリ、別の Project など）は利用側の道具が決めます。実行の計画では、共同で作る範囲と受け渡した版を書きます。
