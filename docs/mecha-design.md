# アニメのメカデザインと玩具化の定義

`mecha-design@1.0.0` は、アニメに出す変形・合体のメカを、企画の要求と合体の構想から決め、シルエットと比率、変形と合体の仕組み、3Dモデルで成り立ちを確かめてから、設定画の決定稿・玩具化の検討・色彩・見せ場の絵と動画へ進める定義です。

**11工程・11成果物・14項目・18引用／網羅規則・23達成条件**。各工程に人が確かめる達成条件があります。AI の達成条件は、見出しと項目の抜け、引用と網羅に限ります。形の良し悪しと商品としての成否は、進め方で決めた人が決めます。

## セクションと工程

| セクション | 工程 | 主な成果物 |
|---|---|---|
| 企画 | 進め方 → 企画と要求 | 進め方、企画と要求 |
| 形 | 合体の構想 → シルエットと比率 | 合体の構想、シルエットと比率 |
| 仕組み | 変形と合体の仕組み → 3Dモデル | 変形と合体の仕組み、3Dモデル |
| 決定稿 | 設定画（決定稿）・玩具化の検討 → 色彩 | 設定画、玩具化の検討、色彩 |
| 見せ場と決定 | 見せ場 → 決定と記録 | 見せ場、判断の記録 |

`after` は工程の**受け入れ順**です。設定画と玩具化の検討は、3Dモデルの受け入れの後に並んで進み、色彩は二つがそろってから受け入れます。作画の色と玩具の色を同じ配色から決めるためです。

## 複数の組織で決める

この定義は、一つのメカに複数の組織の人が関わることを前提にしています。

- 制作の側：監督（作品の中での役割と見せ場）、ディレクター（話数・尺・予定）、メカデザイナー（形と仕組み）。
- 玩具の側：商品の担当（価格・対象年齢・売り場）、設計の担当（保持・強度・安全・費用）。

**進め方**で、工程ごとに呼ぶ人と、どの組織から何人の承認で受け入れるかを決めます。人の達成条件は「誰が何を確かめるか」を書き、承認の数え方（組織と人数）は使う道具の承認の条件で持ちます。議論で出た指摘は**判断の記録**の指摘（IS）に一件ずつ残し、対象の項目を引きます。決定と記録の工程では、指摘がすべて判断（DC）に引かれていること（`issue-covered`）を確かめます。

## 考え方

- 形より先に要求を並べる。監督の見せ場と玩具の商品の条件は、ぶつかることが多い。出した人の立場と優先の順を付けて、後の判断で引く。
- 合体は表と図で先に決める。何機が、どの順に、どの部位になるかを決めてから、シルエットを描く。
- 遠目の影で役割を読ませる。シルエットの段階で細部を描かない。
- 仕組みは手順ごとに確かめる。関節と結合点を一件ずつ挙げ、手順ごとに干渉・届くか・保持を確かめる。3Dモデルの形態ごとの干渉の確認で、絵だけでは見えない破綻を探す。
- AI の出したものは人が見て直す。3Dモデルの「手で直した所」に、AI の案から人が直した所と理由を残す。
- 既存の作品のメカ・名前・標章を写さない。

主な引用：機体は要求を、形態は機体を、手順は関節を、確認は手順を、玩具の確認は要求・関節・手順を引きます。網羅：要求は機体・シルエット・比率・玩具の確認・配色・指摘・判断のどれかに引かれる（理由を書けば除ける）。手順と関節は確認に、指摘は判断に、必ず引かれます。
