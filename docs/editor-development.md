# 新しい Editor の開発

[定義](../definitions/editor-development.json) は、ひとつの題材（マインドマップ、収支、カードなど）を編集する Editor を、Editor のテンプレートから作り、Host に package として取り込んで使えるところまで進めるための定義です。画面のある製品全体を本番まで作るときは software-product を使います。

## いつ使うか

- 既存の Editor や、既存の形式の別の見せ方では足りない題材があるとき
- テンプレートから作った Editor を、手元の Host に取り込んで成果物として使いたいとき

既存の Editor に小さな操作を足すだけなら、その Editor の通常の開発で行えます。

## 工程と成果物

| 工程 | 成果物 | 主な判断 |
| --- | --- | --- |
| 進め方 | 工程の表 | 通る工程、確かめる人、外へ出すもの（リポジトリ・package・Host） |
| 目的と範囲 | 目的と代表操作、能力の表 | 利用者、正常な操作と拒否する操作、新しい Editor が要る理由、対応する能力としない能力 |
| データ形式 | データ形式の仕様 | 形式の名前と版、保存する値と ID、上限、不変条件、保存しない表示の状態 |
| 操作と履歴 | 操作の表 | 変える値、Undo の単位、拒否の条件、外からの提案に出すか |
| 画面と入力 | 画面の設計 | 見えるものと呼べる操作、日本語入力、狭い画面、読み取り専用 |
| 実装 | コード | テンプレートの検査（型・試験・ビルド・package の検証）を通す |
| 検証 | 試験の対応表 | 試験と確かめる対象、結果（通った・落ちた・未実施） |
| 配布と取り込み | 配布と取り込みの記録 | 配布版の ID・版・hash、運用者の pin の確かめ、Host での開く・編集・保存・再読込 |
| 学び | 学び | 次の版・テンプレート・Host・この定義への直し |

工程は **決める → 作って確かめる → 届ける** の 3 つのまとまりです。データ形式は保存した後に変えにくいので、画面より前に決めます。

## 項目・引用・網羅

| ID の形 | 項目 | 引く先 |
| --- | --- | --- |
| `UR-{nn}` | 利用者 | ― |
| `OP-{nn}` | 代表操作 | 利用者（1 件以上） |
| `EX-{nn}` | 扱わないこと | ― |
| `CA-{nn}` | 能力 | 代表操作（任意） |
| `FD-{nn}` | 保存する値 | ― |
| `LM-{nn}` | 上限 | 保存する値（1 件以上） |
| `IV-{nn}` | 不変条件 | 保存する値（1 件以上） |
| `CM-{nn}` | 編集の操作 | 代表操作（1 件以上）、保存する値・不変条件（任意） |
| `SC-{nn}` | 画面 | 代表操作か編集の操作（1 件以上） |
| `TS-{nnn}` | 試験 | 代表操作・操作・不変条件・上限・能力・画面（1 件以上） |
| `RL-{nn}` | 配布版 | ― |
| `HC-{nn}` | 取り込みの確認 | 配布版（1 件以上）、代表操作（任意） |
| `LE-{nn}` | 学び | 代表操作・操作・能力・試験・取り込みの確認（任意） |

網羅の規則：代表操作・編集の操作・不変条件には試験が要ります。どの配布版にも取り込みの確認が要ります。データを変えない代表操作（保存と再読込など）は編集の操作から、上限としないと決めた能力は試験から、理由を書いて除けます。

## 確かめ方の決まり

- 対応すると決めた範囲に「落ちた」か「未実施」が残るとき、その範囲を対応済みとは言いません（`verify.results`）。
- 運用者は、受け取った package の版と hash を自分で確かめてから信頼に登録します。package に同梱された pin をそのまま信頼しません（`package.pin`）。
- Host への取り込みは、成果物から開き、編集・保存・再読込までを確かめて終わりです（`package.approved`）。
