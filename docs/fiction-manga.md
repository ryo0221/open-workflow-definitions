# 漫画の制作の定義

`fiction-manga@1.1.0` は、漫画を企画から出版準備まで進めるための汎用定義です。作品の題材、ページ数、出口、使う道具やファイルの場所はプロジェクト側で決めます。schema は既存の format 1 のままです。

13工程・22成果物・49達成条件です。どの工程にも作者が確かめる条件があります。AI が確かめる条件は、項目どうしの引用・網羅・抜け、決めた表記の照合、決めたレイヤーがそろっているかに限ります。絵や作品の良し悪しを AI の条件で合格にはしません。

## 工程のセクション

| セクション | 工程 | 成果物 |
|---|---|---|
| 企画 | 進め方、企画 | 進め方、企画書、**画作りガイド** |
| 物語設計 | 人物、世界と舞台、筋と構成、脚本 | 人物表・相関図・人物の設定画、世界の覚え書き・**地図**・舞台の設定画・舞台の3Dモデル（任意）・辞書、筋の台帳・構成図、脚本 |
| ネームと作画 | ネーム、ラフ、線画、仕上げと写植 | **ネーム**（ページとコマ）、ラフ、線画、仕上げ、写植の記録 |
| 仕上げと公開 | 通読、出版準備、学び | 編集の記録、出力の記録、学びの記録 |

人物と世界と舞台は、企画の後に並行して進められます。after は受け入れの順です。前の工程を受け入れる前に先のページを試しに描いてかまいませんが、それをその工程の受け入れや前提を満たしたことには数えません。

## 画作りガイドとレイヤーの決まり

画作りガイドは、絵についての決まりの正本です。小説の文体ガイドにあたります。

- **画作りの決まり（AR）**：線・形の誇張・配色・陰影・密度・カメラと演出・人物の固定した外見・許す例外。
- **レイヤーの決まり（LY）**：レイヤーごとに、名前・重ね順・描く中身（下描き・線画・塗り・影・背景・効果・吹き出し・文字など）・使う段階（設定画・ラフ・線画・仕上げ）・分けたまま残すか・人と AI のどちらが描いてよいか。段階ごとに要るレイヤーと、ラフから線画・仕上げへ引き継ぐレイヤーも書きます。
- **採用見本（SM）**：出典・利用条件・外へ送ってよいか・固定した版。
- **文字の決まり**：台詞・擬音・手書き文字の書体と大きさ、縦書き・横書き、ルビ。

人物と舞台の設定画、ラフ、線画、仕上げのどれにも「レイヤー」の見出しがあり、絵ごと（ページごと）に、使ったレイヤーをレイヤーの決まりの名前で書きます。決まりに無いレイヤーを足したときと、分けておくレイヤーをまとめたときは理由を書きます。人が描いた・直したレイヤーと、AI の提案を採ったレイヤーもここに書きます。

AI は、各段階で決まりに要るレイヤーがそろっているかと、理由の抜けを確かめます（`art.layers-defined`・`character.art-covered`・`stage.art-covered`・`rough.layers`・`ink.layers`・`finish.layers`）。構図・ポーズ・人物の同一性・画風・ラフの意図は作者が確かめます。レイヤーの中身を絵のファイルから読み取るのは利用側の役目です。

世界の事実（世界の覚え書き・地図）、人物と場所の同一性（人物表・地図の場所）、絵の画風（画作りガイド）は別の成果物に分けています。同じ世界・人物・ラフから別の画風を作るときは、画作りガイドだけを差し替え、世界や人物の正本を複製しません。

## 地図とネーム

- **地図**は世界と舞台の工程で作る図です。場所（LO）を点、道（RT）を線にして描きます（`view` の `graph`）。場所ごとに位置・向き・縮尺を書き、時点や世界線で様子が変わる場所は前と後を分けて、どの出来事で変わるかを書きます。舞台の設定画は地図と同じ向きと縮尺で描きます。
- **舞台の3Dモデル**（任意）は、場所ごとに地図と同じ向きと縮尺で作ります。作らない作品では、進め方の「省く工程」に省くと書いて空にします。
- **ネーム**（ストーリーボード）はページ（PG）とコマ（PN）を項目にします。コマごとに、人物の配置（FG。どの人物が、舞台のどこに、どちら向きに、どんな姿勢でいるか）とカメラの位置・向き・画角を、舞台の3Dモデルか地図の上で決めます。図ではページとコマを枠、人物の配置を点にして、人物ごとに色を分けます（`view` の `graph`）。人物の配置ごとにコマの上へ、そのコマで描写する範囲のアタリ（頭の向きの十字・胴・関節の分かる腕と脚と、見えるときは目と口）を描き、ネームの段階でポーズと表情が読めるようにします。顔のアップ・後ろ姿・手元だけ・シルエットのように画角の外や意図して描かない部分は、構図か省いた理由を書き、作者が構図と省き方を確かめます。アタリの名前には、どの人物の配置か・ポーズの意図を書きます。ページとコマを読む方向は画作りガイドの文字の決まりに書き、ネームで合っているかを確かめます。ラフでは人物の配置ごとに、そのコマのアングル・ポーズ・表情で人物を描きます。AI が生成した画像を採ったレイヤーには、道具と版・渡した参照・出典と利用条件を書き、人物と舞台の設定画・ラフ・線画・仕上げの、それぞれ採った工程で AI が確かめます。ラフは、この配置とカメラとアタリから下絵を作れます。コマはページを ID の親にしません。コマを別のページへ移しても ID と引用はそのまま残ります。ラフ・線画・仕上げは同じページとコマの後の版で、項目を作り直しません。

## 項目と引用

| 項目 | ID | 置く成果物 |
|---|---|---|
| テーマ | TH-{nn} | 企画書 |
| 画作りの決まり | AR-{nn} | 画作りガイド |
| レイヤー | LY-{nn} | 画作りガイド |
| 採用見本 | SM-{nn} | 画作りガイド |
| 人物 | CH-{nn} | 人物表 |
| 場所 | LO-{nn} | 地図 |
| 道 | RT-{nn} | 地図 |
| 用語 | TE-{nn} | 固有名詞と表記の辞書 |
| 筋 | PT-{nn} | 筋の台帳 |
| 出来事 | EV-{nnn} | 筋の台帳 |
| 伏線 | FS-{nn} | 筋の台帳 |
| 提示位置 | OC-{nnn} | 構成図 |
| シーン | SC-{nnn} | 脚本 |
| 台詞 | DL-{nnn} | 脚本 |
| ページ | PG-{nnn} | ネーム |
| コマ | PN-{nnn} | ネーム |
| 人物の配置 | FG-{nnn} | ネーム |
| 吹き出し | BL-{nnn} | 写植の記録 |
| 指摘 | RV-{nnn} | 編集の記録 |
| 学び | LE-{nn} | 学びの記録 |

引用の規則：筋→テーマ、伏線→筋、道→場所、提示位置→シーン、シーン→出来事・筋と人物・場所（伏線は任意）、台詞→話す人物、コマ→シーン（台詞は任意）、人物の配置→人物、吹き出し→台詞とコマ、指摘→ページ・コマ・シーン・台詞、学び→指摘（任意）。網羅の規則：筋と伏線はシーンで（理由を書けば除ける）、シーンはコマで、台詞は吹き出しで（理由を書けば除ける）扱われていること。

読者への提示順は、小説と同じく構成図の提示位置だけに書きます。ページとコマの並びはネームが持ちます。時間・提示・世界線の書き方は[物語の時間・提示・世界線](fiction-novel-timeline.md)と同じです。

## 利用側が受け持つこと

- **話・ページごとの反復。** ネームから仕上げまでを話やページごとに進めるときの単位、単位ごとの状態、引用先の版が変わったときの再確認。`outline.repeat` は工程の反復には使いません。
- **AI に頼む範囲。** 進め方で決めた範囲を、工程・話・ページ・レイヤーごとの設定と権限として守ること。
- **絵の生成と採否の来歴。** 生成の依頼・使った資料と見本・採否・保存した版を記録し、出版準備の「AI の関わり」に使えるようにします。却下した案や保存に失敗した案を採用済みにしません。
- **レイヤーの読み取り。** 絵のファイルからレイヤーの名前と中身を読み、画作りガイドの決まりと照らせるようにすること。
- **版。** 受け入れた成果物の固定した版、レイヤーを残した元の原稿、出力のもとにした版の記録。

## 小説の定義との関係

`fiction-novel` とは、進め方・企画・人物・筋と構成・通読・出版準備・学びの工程 ID と、人物・場所・出来事・筋・伏線・提示位置・シーン・指摘・学びの項目の名前と ID の形をそろえています。小説の「世界と舞台」（`world`）は世界の覚え書きに場所を置きますが、漫画の「世界と舞台」（`stage`）は場所を地図に置き、配置・向き・縮尺まで決めます。小説を漫画にするときは、漫画の脚本から小説のシーンの固定した版を引用します（版の管理は利用側）。

検査: `node scripts/check.mjs`。これは定義の形と参照の検査です。作品や絵が完成したことは検査しません。
